Part I — The picture before the mathematics

1. What problem is this even solving?

Earthquakes are not scattered randomly through time. They cluster: a big one is followed by a swarm of smaller ones, which have their own smaller swarms, and so on.

There are two completely different reasons a quake can happen: * Background — tectonic stress built up over decades finally releases. These arrive at a slow, roughly steady rate, independent of each other. * Triggered — a previous quake changed the stress nearby and set this one off. These arrive in bursts, clustered right after their parent in both time and space.

ETAS (Epidemic-Type Aftershock Sequence) is the standard statistical model for exactly this. The name is the idea: earthquakes spread like an epidemic. Every quake is "infectious" — it can trigger children, which trigger grandchildren. Big quakes are more infectious than small ones. Infectiousness decays with time and distance.

Why this project cares

The bigger project asks: can a neural network learn structure that ETAS misses? The plan is a multiplicative correction: λ_corrected = λ_ETAS × exp(f_NN)

The network learns a residual on top of ETAS. Which means ETAS has to be right first. If your baseline is miscalibrated, the network spends its capacity learning the baseline's mistakes — and then you measure that as "skill" and congratulate yourself. Garbage baseline, confidently wrong correction.

2. The one idea the whole model rests on

Everything below is built on a single concept. If you get this one, the rest is bookkeeping.

Conditional intensity, $\lambda$ $\lambda(t)$ = the instantaneous rate of earthquakes at time $t$, given everything that has already happened.

The word doing the work is conditional. $\lambda$ is not a fixed number — it depends on history. Right after a big quake, $\lambda$ is huge. Six months later it has decayed back down. It is a function of the past.

Part II — The mathematics, built up piece by piece

4. Gutenberg–Richter: how many big ones per small one

The empirical fact: count the earthquakes above each magnitude, plot the log of the count against magnitude, and you get a straight line.

$$ \log_{10} N(\ge m) = a - b m $$

  • N(≥m) = how many events at or above magnitude m
  • a = overall activity level (a busy region has a big a)
  • b = the slope — the size mix

What b means, intuitively: $b \approx 1$ means: for every M4, there are ten M3s and a hundred M2s. Drop one magnitude unit, multiply the count by $10^b$.

5. $M_c$: the magnitude below which you are blind

$M_c$ = the magnitude of completeness = the smallest magnitude at which the network catches essentially all the events that occurred.

Below $M_c$, quakes happen but are missed — too faint, or buried in noise. So your catalog systematically undercounts down there.

6. Estimating b, and why $M_c$ must come first

Aki (1965) and Utsu (1965) found the maximum-likelihood estimator for the exponential magnitude distribution: $$ \hat{b} = \frac{\log_{10} e}{\bar{m} - (M_c - \Delta m/2)} $$

In words: b is one over (mean magnitude minus threshold), times a constant, with a small correction for binning.

The $\Delta m/2$ is the binning correction. Magnitudes are reported rounded. An event recorded as "2.6" was really somewhere in [2.55, 2.65). Rounding shifts the effective threshold down by half a bin, and Utsu's correction undoes that.

The sensitivity argument

Differentiate $b$ with respect to $M_c$. An error in $M_c$ translates to a massive error in $b$. Quoting b without quoting $M_c$ is meaningless. The number is undefined without its threshold.

7. Omori's law: aftershocks fade like 1/t

The oldest quantitative law in seismology. The rate of aftershocks decays as a power of time since the mainshock: $$ g(t) = (t+c)^{-p} $$ * t = time since the parent quake (days) * p $\approx 1.1$ typically — how fast the decay is. Bigger p = faster fade. * c $\approx$ hours to a day — a small offset that flattens the curve near t = 0.

Without $c$ you'd have $t^{-p}$, which blows up to infinity at t = 0. That's unphysical.

8. Productivity: bigger quakes make more children

$$ \kappa(m) = K e^{\alpha(m - m_0)} $$ Expected number of direct children of a quake of magnitude m. * K = the baseline — children of a reference-magnitude event * α = how steeply productivity grows with magnitude. Exponential, so this is a big lever.

11. The likelihood, and the term everyone forgets

To fit parameters you need a score: how well does a given $\theta = {\mu,K,\alpha,c,p,d,q}$ explain the observed catalog?

$$ \ell(\theta) = \sum \log \lambda(t_i) - \int \lambda(t) dt $$

Term A (The Sum) — "were the events where the model expected them?" Evaluate $\lambda$ exactly where a quake happened. High $\lambda$ = good.

Term B (The Integral) — "but don't cry wolf" Integrate $\lambda$ over the entire space-time window. This is the total number of events the model expects. Subtracting it penalises a model that inflates $\lambda$ everywhere. This is the term people forget, and it is the whole reason the likelihood works.

12. EM and the branching probabilities

$\lambda$ inside the log is itself a sum over all previous events. A log of a sum doesn't factorize. So no parameter has a closed-form solution.

The insight: Suppose you knew exactly which earlier quake triggered the current one. Then the problem shatters into independent easy pieces. You don't know the parentage, but you can estimate it probabilistically — and that's Expectation-Maximization.

The E-step: For each pair, compute what fraction of the total intensity came from parent $i$. This produces an $N \times N$ triggering matrix.

13. Forward Simulation & The Parametric Bootstrap (Phase 10)

If you can fit ETAS, you should be able to simulate it forward. This provides synthetic catalogs for testing and allows us to compute Confidence Intervals using the Parametric Bootstrap.

Branching vs. Ogata Thinning To simulate a synthetic ETAS catalog, there are two primary methods in the literature: 1. Ogata Thinning: Generates points from a dominating homogenous Poisson process and accepts/rejects them. However, because the ETAS intensity $\lambda(t)$ is extremely spiky right after a mainshock, thinning is inefficient and rejects >99% of proposals. 2. The Branching Process (Veen 2006): This is the method we successfully implemented. It draws background events from a Poisson process, and for every event, it recursively draws a number of expected offspring. This is computationally much more efficient for epidemic-type models.

The Parametric Bootstrap Results Because we mathematically aligned the simulator and the estimator, we successfully closed the "Simulate-then-Recover" loop. We ran the Parametric Bootstrap by: 1. Calibrating the model on the true catalog to obtain parameters $\hat{\theta}$. 2. Simulating N synthetic catalogs using $\hat{\theta}$ via our Branching Process algorithm. 3. Re-calibrating the model on each synthetic catalog to get the empirical distribution. 4. Using the spread to calculate the 95% Confidence Intervals (CIs) for our parameters.

What: The estimated $b$-value as a function of the assumed $M_c$ threshold. Why it exists: To prove why $M_c = 2.6$ was chosen. What it proves: Below $M_c=2.6$, the $b$-value is artificially depressed because the network missed small events. At exactly 2.6, it hits a flat plateau. Where the answer stops depending on the threshold, you have cleared the threshold.

Figures 5 & 6 — The Spatial Maps

What: $M_c$ and $b$-value evaluated on a 0.25-degree spatial grid using Constant-N=250 nearest neighbors. Why it exists: Completeness is not a single number. Near dense station clusters, the network detects smaller quakes. What it proves: $M_c$ is heavily correlated with fault lines and sensor density (ranging from 2.7 to 3.0), while $b$-value variations capture crustal stress.

Figure 7 — The Omori Kernel

What: The unnormalised Omori temporal triggering kernel. Why it exists: To visually ground the abstract parameters $c$ and $p$. What it proves: The $c$ parameter flattens the curve near $t=0$ (preventing infinity). Notice the Y-axis is unnormalised. We deliberately corrected the simulator mismatch to align with this exact unnormalised Ogata curve.

Figure 8 — The Ultimate Validation: Time-Rescaling

What: Transformed times against the unit-rate diagonal. Why it exists: The time-rescaling theorem. If the model claims to know when quakes are likely, then "correcting for" its own predictions should erase all structure and leave pure randomness. What it proves: The empirical line remains tightly within the 95% KS bounds. The temporal structure of the sequence is described adequately by the ETAS parameters.

Figure 9 & 10 — EM Convergence and Traces

What: Log-likelihood vs EM iteration, and parameter traces across random restarts. Why it exists: To prove the optimizer actually found the peak of the mountain. What it proves: Zero decreasing steps. The L-BFGS-B optimizer successfully navigates the incomplete-data likelihood, and the physical parameters ($K$, $p$, $\alpha$) robustly identify.

Part IV — The hidden concepts

15. The ideas that decide whether any of it is real

Distinguish "the code is wrong" from "the data can't answer"

This project spent immense effort separating these two concepts: * Code defect: The Shi-Bolt $\sqrt{n}$ mismatch. Fix: Rewrite the equation. * Code defect: The Simulator vs Estimator Omori normalization mismatch. Fix: Align the simulator to the unnormalised mathematical convention. * Data limitation: $\mu$ (background rate) is unidentifiable from a 60-day aftershock window because there are no background quakes in it.

The $\sqrt{n}$ Bug that Broke the Pipeline

The most valuable lesson in the project. The Shi-Bolt uncertainty formula is: $$ \sigma(\hat{b}) = 2.30 \hat{b}^2 \sqrt{ \frac{\sum(m_i - \bar{m})^2}{n(n-1)} } $$ The original code wrote s_m / sqrt(n(n-1)). But the sum of squares is $n \cdot s_m^2$. So the correct expression has an extra $\sqrt{n}$ in the numerator. At $N = 8,253$, the code's error was a factor of 90.85. It made the algorithm think the $b$-value was insanely stable, so the threshold search kept climbing into the empty tail, returning $M_c = 4.80$. Fixing this one mathematical typo collapsed a 2.22-magnitude method disagreement instantly.

The Floating Point Boundary Trap

In IEEE-754 double precision, 2.6 - 0.05 evaluates to 2.5500000000000003. If you generate the threshold using np.arange, it might evaluate to 2.55 exactly. Exactly 156 events in the catalog have magnitude 2.55. One method includes them, one excludes them, shifting the $b$-value by $1.8\sigma$. This is not a bug you can fix; it is a genuine mathematical property of working on a discretized grid.
